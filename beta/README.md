### ขอบเขตของหลักประกัน (อ่านก่อนอ้างอิง)

- **สิ่งที่ CSP กันได้:** การเชื่อมต่อเบื้องหลังจากหน้าเว็บ — fetch / XHR / WebSocket / beacon, การโหลดรูปภาพ ฟอนต์ และสคริปต์จากภายนอก, การ submit form
- **สิ่งที่ CSP (แบบ meta tag) กันไม่ได้:** การพาทั้งหน้าไป URL อื่น — ส่วนนี้รับประกันด้วยตัวโค้ดเอง: ไฟล์ใน `js/` ไม่มี `location.href` / `window.open` / `innerHTML` (มีเฉพาะการเปลี่ยน `location.hash` ภายในหน้า) และตรวจได้ตามขั้นตอนด้านล่าง
- **หลักประกันจริงจึงเป็น "CSP + โค้ดที่ตรวจได้"** — หน้า GitHub Pages เปลี่ยนตามทุก commit ใน repo ดังนั้นสำหรับงานที่มีข้อมูลจริง แนะนำให้ดาวน์โหลด zip ของ release ที่ตรวจแล้วมาใช้แบบ offline และเปิด 2FA ของบัญชี GitHub ที่ดูแล repo
- **JSZip ที่ฝังไว้:** `vendor/jszip.min.js` (3.10.2) SHA-256 `7f839b2d4688b845c105ebf5d2f9803075f91ea0fe72bdaac176c3a04dd3d2c1` — ตรงกับไฟล์ `dist/jszip.min.js` ในแพ็กเกจ npm ที่ดาวน์โหลดมาทุก byte

### วิธีตรวจสอบด้วยตัวเอง (สำหรับ IT / Compliance)

1. **CSP:** เปิด `index.html` ดูบรรทัด `<meta http-equiv="Content-Security-Policy" …>`
2. **ทดสอบจริง:** เปิดหน้าเว็บ กด F12 แล้วไปที่ Console พิมพ์ `fetch('https://example.com')` จะได้ error ว่าละเมิด CSP `connect-src 'none'`
3. **Network:** เปิดแท็บ Network ใน DevTools ระหว่างใช้งาน จะเห็นแค่ไฟล์ของ repo นี้ (html/css/js) ไม่มี request อื่น
4. **ค้นในโค้ด:** ค้นคำ `localStorage`, `sessionStorage`, `indexedDB`, `fetch(`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`, `cookie` ใน `js/` และ `vendor/` จะเจอเฉพาะในคอมเมนต์หรือข้อความบนหน้าจอที่บอกว่า "ไม่ใช้"
5. **Offline:** ดาวน์โหลด repo เป็น ZIP แล้วดับเบิลคลิก `index.html` ใช้งานได้โดยไม่ต้องต่ออินเทอร์เน็ต

> ⚠️ ไฟล์ JSON และ xlsx ที่ได้จากเครื่องมือนี้มีข้อมูลการตรวจสอบ ให้เก็บตามนโยบายข้อมูลลับของบริษัท และ **ห้าม commit ขึ้น repo นี้**

### ฟีเจอร์หลัก

- **กรองตามระดับ RLA:** ใช้ค่าจาก `1. Basic info!C26` อัตโนมัติ หรือเลือกเองได้ (H/M/L/S/ทั้งหมด)
- **ข้อแบบ Maturity:** แสดงคำอธิบาย M1–M5 จากแบบฟอร์ม
- **ปุ่ม "ใส่ N/A ข้อนอกระดับ RLA":** ใส่ N/A ให้เฉพาะข้อที่ยังว่าง ไม่เปลี่ยนข้อที่ประเมินไว้แล้ว
- **แผง Finding ด้านขวา (หน้า Controls):** สร้าง Finding ใหม่ หรือผูก control เข้ากับ Finding ที่มีอยู่ โดยไม่ต้องออกจากหน้า — เติมหมวด (B) และหัวข้อ (D) ให้อัตโนมัติ
- **ไฮไลต์ข้อที่ยังไม่ประเมิน** หลังผ่าน sheet ไปแล้ว (การ์ดขอบส้ม, ป้าย "ค้าง n" ที่เมนู sheet, กล่อง Remarks แบบเดียวกับ Excel)
- **แท็บ Finding:** ปุ่ม `→ control ID` กลับไปยังข้อที่ผูกไว้
- **ตำแหน่งเซลล์:** ทุกช่องแสดงตำแหน่งในไฟล์ ก.ล.ต. (เช่น `4. D1!J6`) ใช้ค้นด้วย Ctrl+F ได้
- **บันทึกส่วนตัวต่อ control:** working note และ evidence ref อยู่ใน JSON เท่านั้น ไม่ถูก export ลงไฟล์ ก.ล.ต.
- **ติดตาม Finding:** สถานะ Open/Closed และวันที่ปิดจริง (อยู่ใน JSON เท่านั้น) พร้อมไฮไลต์ข้อที่เลยกำหนด

### การตรวจฉบับของไฟล์ที่เปิดทาง ②

ประกาศของ ก.ล.ต. ไม่ได้ระบุวันที่ของแบบฟอร์ม และช่อง `K2` เขียนว่า "รอบปี 2569" ทุกฉบับ เมื่อเปิดไฟล์ทาง ② แอปจะแสดง

- **SHA-256** ของไฟล์ที่เลือก (ถ้าตรงกับไฟล์ที่ฝังไว้ จะบอกว่าเป็นต้นฉบับเดียวกันทุก byte)
- **metadata** วันที่สร้าง / แก้ไขล่าสุด / ผู้แก้ไขล่าสุด — วันที่แก้ไขเปลี่ยนทุกครั้งที่มีคนกด Save ใน Excel แต่ไฟล์ที่ Export จากแอปนี้คง metadata ของแบบฟอร์มไว้
- **ฉบับของแบบฟอร์ม** ตัดสินจาก "สูตร" ไม่ใช่วันที่: `6. Result!L6` (ฉบับก่อน อ้างแถว `$271` / ฉบับ 22 ก.ย. 2026 อ้างแถว `$272`) และ `6.1 Result (Cyber Hygiene)!L19` (ฉบับก่อน ว่าง / ฉบับใหม่ มีสูตร)
  - ฉบับ 22 ก.ย. 2026 → ✓
  - ฉบับก่อน → คำเตือน + ปุ่ม **ย้ายข้อมูลไปแบบฟอร์มฉบับ 22 ก.ย. 2026** (ย้ายทุกช่อง รวม working note / สถานะ finding) และแท็บตรวจความครบถ้วนจะเตือนจนกว่าจะย้าย
  - ไม่ตรงกับฉบับที่รู้จัก → คำเตือนให้ตรวจกับเว็บไซต์ ก.ล.ต. (อาจเป็นฉบับใหม่กว่า)

### ข้อควรทราบ

- **`5. Finding!E5` และ `E6`** เป็นช่องที่แบบฟอร์มให้กรอกจำนวนข้อระดับปานกลาง/ต่ำเอง — เครื่องมือนับจาก Finding และเขียนให้ตอน Export (E4 ระดับสูงเป็นสูตรของแบบฟอร์ม)
- **การ Export:** แก้เฉพาะเซลล์ที่ต้องกรอกใน XML ของไฟล์ ส่วนอื่นไม่ถูกแตะ ได้แก่ สูตร, array formula, กราฟ, data validation, sheet protection และ sheet ที่ซ่อนไว้ เซลล์ที่มีสูตรจะไม่ถูกเขียนทับเด็ดขาด
- **LibreOffice:** อาจไม่คำนวณสูตรใหม่ตอนเปิดไฟล์ ถ้าเปิดด้วย LibreOffice ให้กด `Ctrl+Shift+F9`
- **ใช้กับแบบฟอร์มรอบปี 2569 เท่านั้น:** ผังเซลล์อยู่ใน `js/template-2569.js` ถ้าโหลดไฟล์ปีอื่นจะมีคำเตือน ปีถัดไปให้ทำ repo ใหม่ (เช่น `sec-itaudit-form-2027`)

## การ Deploy ด้วย GitHub Pages (ทำผ่านหน้าเว็บ GitHub ได้ทั้งหมด)

2. กด **Add file → Upload files** แล้วลากไฟล์และโฟลเดอร์ทั้งหมด (`index.html`, `README.md`, `CHANGELOG.md`, `css/`, `js/`, `vendor/`, `fonts/`) ลงไป จากนั้น Commit

4. รอสักครู่ หน้าเว็บจะอยู่ที่ `https://<username>.github.io/sec-itaudit-form-2026/`
